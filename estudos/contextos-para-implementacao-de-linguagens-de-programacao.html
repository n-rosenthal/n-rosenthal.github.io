Definições

Binding

Um binding é uma associação entre um identificador e uma informação.

\[ x \mapsto b \]

O identificador pode representar uma variável, função, constante ou qualquer outro elemento nomeado da linguagem.

O valor associado pode representar:

  • um tipo;
  • um termo;
  • um valor;
  • uma definição;
  • uma substituição;
  • uma informação específica da linguagem.

Contexto

Um contexto é uma coleção de bindings que registra informações necessárias à interpretação de uma expressão.

Na notação da semântica formal, é frequentemente representado por Γ.

\[ \Gamma = [x_1 \mapsto b_1,\ldots,x_n \mapsto b_n] \]

A operação de extensão adiciona uma associação:

\[ \Gamma' = \Gamma, x \mapsto b \]

A associação recém-adicionada passa a ser a mais recente.

Contextos persistentes

Um contexto persistente é uma estrutura na qual operações de extensão produzem novos contextos sem modificar os anteriores.

\[ \Gamma' = \operatorname{extend}(\Gamma,x,b) \]

A estrutura original continua disponível.

Essa propriedade é particularmente útil para representar escopos lexicais: cada extensão pode representar a entrada em um novo escopo.

Sombreamento

Sombreamento ocorre quando uma associação mais recente utiliza um identificador já presente no contexto.

Considere:

\[ \Gamma_0 = [x \mapsto 1] \]

\[ \Gamma_1 = \Gamma_0, x \mapsto 2 \]

A consulta no contexto mais recente deve retornar:

\[ \operatorname{lookup}(\Gamma_1,x)=2 \]

O binding anterior continua existindo na estrutura persistente, mas deixa de ser o resultado da consulta nominal.

Implementação

Reutilização de LinkedList

A estrutura LinkedList<T> já implementa uma lista encadeada persistente com armazenamento de nomes e valores.

Sua representação conceitual é: 

pub struct LinkedList<T> {
    head: Option<Rc<Node<T>>>,
    len: usize,
}

Cada nó contém: 

pub struct Node<T> {
    name: String,
    value: T,
    parent: Option<Rc<Node<T>>>,
}

A estrutura já é responsável por:

  • armazenamento dos elementos;
  • compartilhamento estrutural;
  • extensão persistente;
  • iteração;
  • consulta por nome;
  • consulta por índice;
  • destruição da estrutura.

Portanto, a implementação de Context não deve reproduzir essas responsabilidades.

Representação de Context

A representação do contexto é deliberadamente simples: 

pub struct Context<B> {
    bindings: LinkedList<B>,
}

O nome está armazenado no nó da lista, enquanto o valor armazenado é o binding.

Assim, não precisamos de uma segunda estrutura: 

// Desnecessário quando LinkedList já armazena nomes.
pub struct Binding<B> {
    pub name: String,
    pub value: B,
}

A associação entre nome e valor já é fornecida pela própria lista.

Responsabilidades

A separação de responsabilidades é:

Componente Responsabilidade
LinkedList Estrutura persistente e armazenamento
Context Operações semânticas sobre bindings
Node Representação interna de um elemento
Rc Compartilhamento estrutural

O contexto não precisa conhecer a implementação dos nós.

Operações

Construção

Um contexto vazio é construído a partir de uma lista vazia: 

pub fn empty() -> Self {
    Self {
        bindings: LinkedList::empty(),
    }
}

Extensão

A extensão delega a operação à lista: 

pub fn extend(
    &self,
    name: impl Into<String>,
    binding: B,
) -> Self {
    Self {
        bindings: self.bindings.extend(binding, name),
    }
}

O contexto original não é modificado.

Consulta por identificador

A consulta nominal também é delegada: 

pub fn lookup(&self, name: &str) -> Option<&B> {
    self.bindings.lookup(name)
}

Como a lista percorre os elementos do mais recente ao mais antigo, o primeiro binding encontrado corresponde ao binding visível.

Consulta por índice

A consulta por índice utiliza a ordem mais recente primeiro: 

pub fn lookup_index(&self, index: usize) -> Option<&B> {
    self.bindings
        .iter()
        .nth(index)
        .map(|(_, binding)| binding)
}

Essa operação é adequada à implementação de índices de De Bruijn.

Iteração

A iteração preserva as duas ordens úteis: 

/// Mais recente para mais antigo.
pub fn iter(&self) -> impl Iterator<Item = (&str, &B)> {
    self.bindings.iter()
}

/// Mais antigo para mais recente.
pub fn bindings(&self) -> Vec<(&str, &B)> {
    self.bindings.values()
}

A escolha da ordem depende da operação semântica.

Para resolução de variáveis e índices de De Bruijn, a ordem mais recente primeiro é conveniente.

Para exibição e reconstrução da sequência de extensões, a ordem mais antiga primeiro pode ser mais apropriada.

Contextos genéricos

A abstração pode ser utilizada para diferentes categorias de informação.

Contexto de tipos

\[ \Gamma = [x_1:T_1,\ldots,x_n:T_n] \] 

pub type TypeContext<T> = Context<T>;

Utilização: 

let context: TypeContext<Type> = Context::empty()
    .extend("x", Type::Integer)
    .extend("y", Type::Boolean);

Contexto de valores

\[ \rho = [x_1 \mapsto v_1,\ldots,x_n \mapsto v_n] \] 

pub type ValueContext<V> = Context<V>;

Contexto de termos

pub type TermContext<T> = Context<T>;

Pode armazenar definições nomeadas, expressões ou termos associados a identificadores.

Contexto de substituições

pub type SubstitutionContext<S> = Context<S>;

Pode representar associações utilizadas durante operações de substituição.

Ambiente de execução

pub type Environment<V> = Context<V>;

Um ambiente de execução associa variáveis a valores.

Relação com a semântica formal

Julgamentos de tipagem

Um julgamento de tipagem tem a forma:

\[ \Gamma \vdash t : T \]

O contexto Γ fornece os tipos das variáveis livres de t.

Por exemplo, uma regra de variável pode ser representada por:

\[ \frac{x:T \in \Gamma} {\Gamma \vdash x:T} \]

A operação lookup fornece a associação necessária para verificar a premissa.

Avaliação

Na semântica operacional, um ambiente pode ser representado por:

\[ \rho = [x_1 \mapsto v_1,\ldots,x_n \mapsto v_n] \]

A avaliação de uma variável utiliza o ambiente:

\[ \langle x,\rho\rangle \Downarrow \rho(x) \]

Escopos lexicais

A persistência permite representar diferentes escopos sem modificar ambientes anteriores.

Por exemplo:

\[ \rho_0 = [] \]

\[ \rho_1 = \rho_0, x \mapsto 10 \]

\[ \rho_2 = \rho_1, y \mapsto 20 \]

Cada ambiente preserva a estrutura anterior.

Índices de De Bruijn

Índices de De Bruijn substituem nomes de variáveis por índices que representam a distância até a abstração correspondente.

Considere:

\[ \Gamma = [x \mapsto b_x,\; y \mapsto b_y,\; z \mapsto b_z] \]

Com o binding mais recente no índice zero:

Índice Variável
0 z
1 y
2 x

A consulta por índice é:

\[ \operatorname{lookupIndex}(\Gamma,i) \]

Essa convenção deve ser mantida consistentemente nas operações de deslocamento, substituição e interpretação de termos nameless.

Estratégias de armazenamento

LinkedList

A implementação baseada em lista persistente é apropriada quando:

  • é necessário preservar versões anteriores do contexto;
  • há muitos escopos aninhados;
  • sombreamento precisa ser preservado;
  • consultas por índice são frequentes;
  • a ordem de inserção possui significado semântico.

HashMap

A implementação baseada em mapa é apropriada quando:

  • a consulta por identificador é predominante;
  • não é necessário preservar associações anteriores;
  • a substituição de bindings é aceitável;
  • a ordem dos elementos não é semanticamente relevante.

As duas implementações não devem ser consideradas semanticamente intercambiáveis sem que suas diferenças sejam explicitadas.

Testes e propriedades

A implementação deve verificar as seguintes propriedades.

Persistência

A extensão não modifica o contexto original:

\[ \Gamma' = \operatorname{extend}(\Gamma,x,b) \]

\[ \Gamma \neq \Gamma' \]

quando a extensão adiciona uma associação nova.

Sombreamento

Uma associação mais recente deve prevalecer na consulta nominal:

\[ \operatorname{lookup}( \Gamma,x ) = b_{\text{recente}} \]

Indexação

O índice zero deve representar o binding mais recente:

\[ \operatorname{lookupIndex}(\Gamma,0) = \operatorname{last}(\Gamma) \]

considerando a sequência de extensões.

Ordem de iteração

As operações de iteração devem respeitar as convenções documentadas.

Igualdade

A igualdade estrutural deve considerar os nomes, os valores e a ordem dos bindings.

Decisões de implementação

  1. Context<B> utiliza LinkedList<B>.
  2. A lista é a única responsável por armazenar os nomes e os valores.
  3. Não há uma segunda implementação de Node.
  4. Não há gerenciamento próprio de Rc em Context.
  5. Não há implementação própria de Drop em Context.
  6. A extensão é persistente.
  7. O binding mais recente tem precedência em consultas nominais.
  8. O índice zero corresponde ao binding mais recente.
  9. A implementação baseada em mapa possui semântica documentada separadamente.
  10. Os contextos de tipos, valores, termos e substituições são especializações da abstração genérica.
